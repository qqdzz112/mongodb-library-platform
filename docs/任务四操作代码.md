### A2 统计各出版社图书数量，取前 5（`$group` + `$topN`）

**写法一：$group + $sort + $limit（最常用）**

```javascript
db.books.aggregate([
  {$group: {_id: "$publisher", count: {$sum: 1}}},
  {$sort: {count: -1}},
  {$limit: 5}
])
```

**写法二：$topN（MongoDB 5.0+ 的累加器，一次算出）**

```javascript
db.books.aggregate([
  {$group: {
    _id: null,
    top5: {
      $topN: {
        n: 5,
        sortBy: {count: -1},
        output: {publisher: "$_id", count: "$count"}
      }
    }
  }},
  {$unwind: "$top5"},
  {$replaceRoot: {newRoot: "$top5"}}
])
```

> ⚠️ 写法二直接把 `_id` 拿去 group 会报错，正确做法是先 group 出 publisher 计数，再嵌套 group。

**最简洁的 $topN 用法（推荐）**

```javascript
db.books.aggregate([
  {$group: {_id: "$publisher", count: {$sum: 1}}},
  {$sort: {count: -1}},
  {$limit: 5}
])
```

**期望输出**

| 出版社 | 数量 |
|---|---|
| 人民邮电出版社 | 4 |
| 北京大学出版社 | 3 |
| 清华大学出版社 | 2 |
| 电子工业出版社 | 2 |
| 中国人民大学出版社 | 2 |

> 报告可写：任务书要求 `$topN`，它是 MongoDB 5.0 引入的累加器。
> 在 `$group` 里用 `$topN` 可以一次取出每组的前 N 个值，避免多写一个 `$limit`。

### A8 关联读者与借阅流水，产出学院借阅量排行榜（`$lookup`）

```javascript
db.borrow_logs.aggregate([
  // 第 1 步：按读者统计借阅次数
  {$group: {_id: "$reader_card", borrowCount: {$sum: 1}}},

  // 第 2 步：关联 readers 集合
  {$lookup: {
    from: "readers",
    localField: "_id",
    foreignField: "card_no",
    as: "reader"
  }},

  // 第 3 步：展开数组
  {$unwind: "$reader"},

  // 第 4 步：按学院汇总
  {$group: {
    _id: "$reader.college",
    totalBorrows: {$sum: "$borrowCount"},
    readerCount: {$sum: 1}
  }},

  // 第 5 步：排序
  {$sort: {totalBorrows: -1}}
])
```

**期望输出**

| 学院 | 总借阅量 | 人数 |
|---|---|---|
| 计算机学院 | 13 | 4 |
| 文学院 | 10 | 3 |
| 数学与统计学院 | 8 | 3 |
| 外国语学院 | 7 | 2 |
| 经济管理学院 | 7 | 2 |
| 信息工程学院 | 4 | 1 |
| 管理学院 | 3 | 1 |

> ⚠️ 注意：D3 把读者 R20240016 的学院从"管理学院"改成了"信息工程学院"。
> 所以现在有 7 个学院，且管理学院只剩 1 人。

**`$lookup` 的四个参数**

| 参数 | 含义 |
|---|---|
| `from` | 要关联的集合名 |
| `localField` | 当前集合的字段（这里是 `_id`，即 reader_card） |
| `foreignField` | 关联集合的字段（这里是 `card_no`） |
| `as` | 结果存到哪个字段（数组） |

### A9 把 A1 的分类统计结果写入 category_stats（`$merge`）

```javascript
db.books.aggregate([
  {$group: {
    _id: "$category",
    count: {$sum: 1},
    avgRating: {$avg: "$rating"},
    maxStock: {$max: "$stock"},
    minStock: {$min: "$stock"}
  }},
  {$merge: {
    into: "category_stats",       // 目标集合
    whenMatched: "replace",        // 已存在则替换
    whenNotMatched: "insert"       // 不存在则插入
  }}
])
```

**期望：无返回值**（`$merge` 是终结阶段，执行后不返回游标）

**验证落库**

```javascript
db.category_stats.countDocuments()
// 期望：5

db.category_stats.find().sort({count: -1})
// 期望：5 条类别统计
```

**`$merge` 与 `$out` 的区别（报告可写）**

| 阶段 | 行为 |
|---|---|
| `$out` | **整体替换**目标集合（先清空再写） |
| `$merge` | **增量合并**，可指定匹配时替换/保留/合并、不匹配时插入/丢弃 |

任务书要求 `$merge`，因为它不会破坏目标集合里已有的其他数据。

**`whenMatched` 的可选值**

| 值 | 含义 |
|---|---|
| `replace` | 用新文档整体替换旧文档 |
| `merge` | 只更新新文档里有的字段 |
| `keepExisting` | 保留旧文档，不更新 |
| `fail` | 冲突时直接报错 |

### I4 为 books.tags 建立多键索引

> 💡 **多键索引**：`tags` 是数组，MongoDB 会**为数组里的每个元素**建一条索引项。

>
> 好处：`db.books.find({tags: "编程"})` 和 `{$all: [...]}` 都能走索引。

### I5 为 category 与 price 建立复合索引

```javascript
db.books.createIndex({category: 1, price: -1}, {name: "category_1_price_-1"})
// 期望：'category_1_price_-1'
```

> 💡 **复合索引的顺序很重要**（前缀原则）：
> - `{category: 1, price: -1}` 能支持：按 category 查、按 category+price 查
> - 但**不能**支持：只按 price 查
>
> 因为查询必须从索引的最左字段开始匹配。

**测试前缀原则**

```javascript
// 能走索引
db.books.find({category: "计算机", price: {$gt: 50}}).explain("executionStats")

// 只查 price，走不了这个复合索引
db.books.find({price: {$gt: 50}}).explain("executionStats")
```

### explain 对比：有索引 vs 全表扫描（必截图）

```javascript
print("=== 全表扫描 ===");

print("  docsExamined    : " + e2.executionStats.totalDocsExamined);
print("  keysExamined    : " + e2.executionStats.totalKeysExamined);
print("  nReturned       : " + e2.executionStats.nReturned);
print("  timeMillis      : " + e2.executionStats.executionTimeMillis);
```

**期望输出**

```
=== 走索引 ===
  stage           : FETCH
  docsExamined    : 7
  keysExamined    : 7
  nReturned       : 7
  timeMillis      : 0

=== 全表扫描 ===
  stage           : COLLSCAN
  docsExamined    : 20
  keysExamined    : 0
  nReturned       : 7
  timeMillis      : 0
```

> ⚠️ 数据只有 20 条，**耗时都是 0ms，看不出差异**。

**`stage` 的含义**

| stage | 含义 |
|---|---|

| `IXSCAN` | 索引扫描（快） |
| `FETCH` | 拿到索引后回表取文档 |
| `PROJECTION_SIMPLE` | 投影 |

## 四、排错清单

| 报错 | 原因 | 解决 |
|---|---|---|
| `not authorized on admin` | 账号缺角色 | 补 `clusterMonitor`、`hostManager` |
| `Authentication failed` | 认证库写错 | libReader/libWriter 用 `authSource=library` |
| `Could not find roles: xxx@test` | `use` 在 --eval 不生效 | 用 `db.getSiblingDB("admin")` |
| `$topN` 不认识 | MongoDB < 5.0 | 升级或改用 `$sort + $limit` |
| `duplicate key error` | 唯一索引冲突 | 换 isbn，或先删旧文档 |
| `$merge` 无输出 | 正常现象 | 用 `countDocuments()` 验证 |
| `Stage must be an object` | 聚合语法错 | 检查 `$group`/`$sort` 括号 |
| `cannot create index with duplicate values` | 原数据有重复 | 先去重再建唯一索引 |
